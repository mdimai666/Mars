## Решения и инварианты (переживают план)

1. **Порядок: сначала контракт результата, потом визуал** — UI на `string[][]` пришлось бы переделывать дважды.
2. **Правка ячейки = сгенерированный `UPDATE` + показ SQL + выполнение по кнопке** (стиль phpMyAdmin/DataGrip).
   Автоприменение по Enter/blur (Airtable) отклонено — опасно на чужих БД. Правка только в режиме таблицы
   и только при наличии PK.
3. **«Пагинация» = серверный `MaxRows` + кнопка «показать больше»**, без OFFSET-обёртки над произвольным SQL.
   `MaxRows = 0` — без ограничения (так потоки и `SqlNode` не меняют поведение), UI сам задаёт лимит.
4. **Лимит просмотра объекта — 50 строк в самом SQL** (`LIMIT`/`TOP`), «всего N» считается только для
   «нашего» запроса (вкладка открыта кликом по объекту и SQL не правили) и только фоново с таймаутом 5 с.
5. **Подтверждение опасного SQL**: `SqlSafety.IsDestructive` — `DROP/TRUNCATE/ALTER/GRANT/REVOKE` всегда,
   `DELETE`/`UPDATE` без `WHERE`. Отдельного флага «источник только для чтения» нет — редактор и так
   исполняет любой SQL.
6. **Вьюхи**: только обычные (матвьюхи и карта зависимостей — вне фазы), `CREATE OR REPLACE` (psql/mysql) /
   `CREATE OR ALTER` (mssql), тело проверяется на «ровно один SELECT», автоматический drop+create не делаем —
   показываем ошибку движка. Тело берётся из редактора рабочей области, а не правится в диалоге: у
   `CodeEditor2` нет события изменения, предпросмотр обязан совпадать с тем, что выполнится.
7. **Многоячейковый ноутбук (Jupyter) отложен.** Если делать — явные ячейки + общее соединение на вкладку.
8. **Структура модуля**: агрегатор `Mars.Datasource` (`AddDatasource`/`UseDatasource`) — единственная точка
   подключения, ядро не знает провайдеров (они регистрируются своими хуками из DI); пакеты в NuGet — только
   `Contracts` и `Abstractions`; WASM-админка видит лишь `Contracts` + `Front`.
9. **Инвариант совместимости**: `QueryResultDto.Data` — `[JsonIgnore]`-проекция (заголовки + строки,
   `NULL` → `""`); её читают `Mars.Datasource.Host/Nodes/SqlNodeImpl.cs` и
   `Mars.Modules/Mars.AiChat.Host/Tools/MarsSqlTools.cs` (`FormatRows`). Оба ходят в сервис, не в HTTP —
   проекцию не ломать.
10. Вне плана: ИИ-фичи (кроме кнопки «AI help»), привязка метаполей к SQL, мультиязычие, «визуальные ноды
    вместо IDE», редактирование sequences/ролей.

## Грабли SQL-мира

- **Строковые параметры psql отправляются как `NpgsqlDbType.Unknown`** (хук `ConfigureParameter` в базовом
  ADO-драйвере). Иначе `text` против uuid-колонки давал `42883: operator does not exist: uuid = text` и
  правка ячейки падала почти на всех таблицах Mars (у постов uuid-ключи). MsSQL/MySQL приводят строку сами.
- **В контракте значение полное, показ — усечённый** (даты без секунд/долей/пояса, guid «начало…конец»,
  ячейка 330px). Полное значение отдаётся в `title`, `data-full` (копирование выделения подменяет усечённый
  текст) и в редакторе — иначе правка ячейки вернула бы в базу усечённое время.
- **psql-массивы форматируются литералом Postgres** (`{a,"b,c"}`), `byte[]` — base64; такое значение можно
  вернуть в `UPDATE` параметром.
- **Scoped css не применяется к элементам FluentUI** (`b-`атрибут вешается только на свои элементы) — нужен
  `::deep`, и `min-width: 0` каждому звену flex-цепочки, иначе широкая таблица растягивает страницу.
- **`ColumnSize` — `long?`, не `int?`** (MySQL `longtext` = 4294967295 → `OverflowException` при открытии
  объекта). Регрессия: `MySqlDatasourceTests.DatabaseStructure_LongTextColumn_SizeAboveInt32`.
- **Postgres `CREATE OR REPLACE VIEW` не даёт убрать колонку** (`42P16`); добавлять — можно. В MsSQL/MySQL
  замена с другим составом колонок проходит. Это выбранное поведение, зафиксировано тестом.
- **DDL сбрасывает кэш структуры** (первое слово `CREATE|ALTER|DROP|REFRESH|TRUNCATE`) — иначе дерево до
  конца TTL показывало старое.
- Общие грабли (WASM, `IFileStorage`, `CodeEditor2`, `MarsAppVersion`) — в §7 плана этапа 2.

## Открытые вопросы (не закрыты на момент закрытия плана)

- SQL-автокомплит по схеме: нужен свой completion provider в Monaco (дороже, чем кажется).
- Сохранённые запросы, история и состояние вкладок: не сделаны, где хранить (БД / `localStorage`) — не решено.
- Отмена запроса из UI: токен доходит до БД и отмена по разрыву HTTP-соединения работает, но
  `CancellationToken` в методах клиента и кнопки нет.
- Сортировка кликом по заголовку грида.
- `SqlSafety.IsDestructive` не относит `CREATE` к опасным → `CREATE OR REPLACE VIEW` из редактора
  выполняется без подтверждения (диалог вьюх подтверждает сам). Расширять список — отдельное решение.
- Google Sheets, HTTP/REST как таблица → ушли в план этапа 2 (rest-kind сделан, Sheets в очереди).
- Backup в UI: остаётся действием psql-провайдера (с этапа F плана 2 кнопки рисуются из каталога действий,
  у других kind'ов их просто нет).

## Отклонено

Автоприменение правки ячейки · OFFSET-обёртка для пагинации (ломается на `WITH`, `;`, DDL) ·
`ctid`/`rowid` вместо PK · флаг «только чтение» на источник · редактирование sequences/ролей ·
многоячейковый ноутбук · перенос `SqlQueryJson` (вложенного вида) в MsSQL/MySQL — вложенный JSON собран
на клиенте как представление тех же плоских данных, `SqlQueryJson` позже удалён совсем (этап F плана 2).
