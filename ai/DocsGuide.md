# Mars Documentation Guide for Agent

Как правильно писать и добавлять документацию в Mars. Здесь описана конвенция публичного сайта
документации (`docs/dev_docs/`) и отличие от служебных гайдов для ИИ-агентов (`ai/`).

## Куда класть документ

| Место | Назначение | Публикуется |
|---|---|---|
| `docs/dev_docs/` | Пользовательская/разработческая документация — попадает на сайт документации | Да |
| `ai/` | Контекст и инструкции для ИИ-агентов (как устроен проект, как делать фичи) | Нет |

Если задача — «опиши фичу для пользователей/разработчиков», пиши в `docs/dev_docs/`.
Если — «оставь инструкцию агенту, как это делать дальше», пиши в `ai/`.

## Как устроен сайт документации (`docs/dev_docs/`)

- Все `.md`-файлы из `docs/dev_docs/` встраиваются как embedded-ресурсы в `docs/MarsDocs.WebApp`
  и рендерятся сайтом документации.
- **Структура папок = дерево меню.** Папка становится разделом (подменю), файлы — пунктами.
  Пример: `dev_docs/Plugins/PluginGettingStart.md` → раздел «Plugins», пункт «PluginGettingStart».
- Каждый файл отдаётся по пути `md/{путь-относительно-dev_docs}`.
- Dev-сервер (`MarsDocs.DevServer`) раздаёт `dev_docs` прямо с диска по `/dev_docs` и следит за
  изменениями `.md` (hot-reload) — удобно для предпросмотра.

## Метаданные файла: Title и Order

В **самом верху файла, до первого заголовка `#`**, можно указать метаданные HTML-комментариями
вида `<!-- Ключ: Значение -->`. Парсер (`MarkdownMetadataReader`) читает строки вида
`^<!--\s*(\w+)\s*:\s*(.*?)\s*-->$` и останавливается на первом `#`-заголовке. Ключи нечувствительны к регистру.

Используемые ключи:

- **`Title`** — отображаемое имя пункта меню. Если не задан, берётся имя файла без расширения.
- **`Order`** — числовой порядок сортировки в меню (float). Если не задан или некорректен — по умолчанию `10`.

Пример шапки (как в `docs/dev_docs/QuickStart.md` и `docs/dev_docs/AiChat.md`):

```markdown
<!-- Title: ИИ-чат (агент) -->
<!-- Order: 2 -->


# ИИ-чат (агент)

Текст документации…
```

Рекомендации:

- Ставь `Title` на русском, человечный (это имя видно в меню).
- Задавай `Order` для верхнеуровневых страниц, чтобы управлять их положением
  (`QuickStart.md` — `Order: 1`, `AiChat.md` — `Order: 2`). Для вложенных страниц можно не задавать.
- После шапки метаданных оставь пустую строку и затем `# Заголовок` — сам заголовок H1 тоже нужен,
  он рендерится как название страницы.

## Стиль и оформление

- Язык — русский (как у остальных документов `dev_docs`).
- Имена файлов — `PascalCase.md`, короткие и понятные (`QuickStart.md`, `AiChat.md`, `CreateFirstNode.md`).
- Структурируй заголовками `##`/`###`, списками, блоками кода.
- Блоки кода помечай языком (```csharp, ```json, ```ps1 …).
- Внутренние ссылки на другие файлы документации — относительные, например
  `[описание файлов](md/Structure/MarsFilesStructure.md)`.
- Ссылки на исходники/гайды в репозитории — относительные от файла, например из
  `docs/dev_docs/AiChat.md`: `[ai/AiChatGuide.md](../../ai/AiChatGuide.md)`.

## Чек-лист добавления новой страницы документации

1. Определить раздел: существующая папка (`AppFront`, `Nodes`, `Plugins`, `Structure`) или корень `dev_docs`.
2. Создать `Имя.md` с шапкой `<!-- Title: … -->` (+ `<!-- Order: … -->` для верхнего уровня), пустая строка, `# Заголовок`.
3. Написать содержимое на русском, с заголовками и примерами кода.
4. При необходимости связать ссылками с соседними страницами и с `ai/`-гайдами.
5. Файл подхватится сайтом автоматически (встраивается при сборке `MarsDocs.WebApp`); для локальной
   проверки — `MarsDocs.DevServer` (`/dev_docs`).
