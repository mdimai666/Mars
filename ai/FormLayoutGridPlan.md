# План: конструктор раскладки формы (сетка, drag&drop)

> **Статус: L0–L5 выполнены 2026-09-12**, ветка `ai/form-engine-simplify`, коммит на шаг.
> Продолжение [FormEngineSimplifyPlan.md](./FormEngineSimplifyPlan.md) (там R0–R9: плоское ядро,
> метаполя — обычные поля данных). Этот план меняет **представление** формы (раскладка) и её
> дизайнер; ядро значений, редакторы и реестры не трогает. Итог и сознательные расхождения —
> в конце файла.

## Зачем

Сегодня раскладка формы — плоский список полей: зона → один неявный ряд → поле = ячейка
(`col-12` / `col-12 col-md-6` / `col-12 col-md-4`). Дизайнер (`FormLayoutEditor`) правит этот
список стрелками ↑/↓ и селектами. Хочется настоящую сетку: ряды, колонки (в т.ч. пустые),
вложенность, drag&drop, контейнеры-табы и элементы, которые не поля (заголовок, разделитель).

## Принятые решения (2026-09-12)

1. **Хранение — плоский массив узлов, дерево — модель потребителей.** Узел несёт `Parent` и
   `Kind`; порядок в массиве = порядок внутри родителя (adjacency list). Парные маркеры
   (`row-start`/`row-end`) отвергнуты: дерево из парных маркеров нормализатор не проверит дёшево,
   пустой контейнер неотличим от забытого, перенос поддерева — перенос среза с балансировкой.
2. **Один проектор плоское↔дерево** — `FormLayoutTree` в `Mars.Forms.Contracts`. Потребителей
   двое: **рендерер** формы (ему тоже нужна вложенность) и **дизайнер**. Не по одному сборщику
   дерева на каждого.
3. **Ширина — у колонки, пресеты 12/6/4/3** (`FormItemWidths`: `full`/`half`/`third`/`quarter`).
   У поля своей ширины нет — растягивается по колонке. Одиночное поле «на половину» = ряд из
   колонки(6) и пустой колонки(6).
4. **Пустая колонка занимает место**: рендерится как пустой `col-*`, в дизайнере — штриховой
   плейсхолдер-дропзона.
5. **Секции упраздняются.** Вместо маркера `SectionTitle` — неполевые элементы `Heading`
   (заголовок) и `Divider` (разделитель), которые кладутся в колонки как обычные узлы. Набор
   типов узлов расширяемый: новый элемент = новое значение `Kind` + ветка рендера.
6. **`Container` — новая сущность внутри зоны**, рендерится табами (`FluentTabs`). Зоны
   (`main`/`publish`/`extra`) и их места в форме поста не меняются: контейнеры — надстройка
   внутри зоны. Один контейнер в зоне → табов нет; ноль контейнеров (сегодняшние раскладки) →
   корневые дети зоны прямо, как сейчас.
7. **Легаси читается без миграции.** Старый элемент (`key/zone/title/visible/width/sectionTitle`,
   без `kind`/`parent`) — валидный узел: `Kind = Field`, `Parent = null`, а `sectionTitle` →
   `Heading`. Пишем только новый формат; старая раскладка в `post_types.Options["form"]`
   открывается как есть.
8. **Натуральная ширина («как сам компонент») — вторая итерация.** Сегодня `Width = null` = full;
   оставляем так, чтобы не поехали существующие раскладки. Значение `auto` + источник натуральной
   ширины у ключа редактора в `FormEditorLocator` — отдельным шагом после L5.

## Целевая модель

Один тип и для хранения, и для рантайма (дескриптор поля заполняет только провайдер — как сейчас):

```csharp
public record FormItem
{
    public required string Key { get; init; }   // id узла: у поля — ключ поля, у структурных — сгенерированный
    public string? Parent { get; init; }        // Key родителя; null — корень зоны
    public string? Zone { get; init; }          // только у корневых узлов зоны
    public FormItemKind Kind { get; init; } = FormItemKind.Field;
    public string? Title { get; init; }         // переопределение заголовка поля / текст заголовка / имя таба
    public bool Visible { get; init; } = true;
    public string? Width { get; init; }         // колонка: full|half|third|quarter (null = full)
    public FormFieldDescriptor? Field { get; init; }  // рантайм; в раскладке не хранится
}

public enum FormItemKind { Field, Row, Column, Heading, Divider, Container }
```

Допустимые родители (остальное при нормализации переезжает в корень зоны — поддерево сохраняется):

| Kind | Где допустим |
|---|---|
| `Container` | корень зоны |
| `Row` | корень зоны, `Container`, `Column` |
| `Column` | `Row` |
| `Field`, `Heading`, `Divider` | корень зоны (легаси-плоская раскладка), `Container`, `Row` (неявная ячейка), `Column` |

Разметка рендера:

```
Container  <FluentTabs> табов = контейнеров (только если их ≥ 2)
Row        <div class="row">
Column     <div class="col-12 col-md-N">      N = 12|6|4|3; без детей — пустой div
Field      <FormFieldRow> во всю ширину колонки
Heading    <h6>текст</h6>
Divider    <hr>
```

Поле, лежащее в ряду/зоне напрямую (легаси), рендерится как неявная ячейка `col-N` по ширине
узла — классы должны остаться теми же, что сегодня.

Хранимый json (пример):

```json
{ "items": [
  { "key": "main-tab-1", "kind": "container", "zone": "main", "title": "Основное" },
  { "key": "row-1", "kind": "row", "parent": "main-tab-1" },
  { "key": "title", "kind": "field", "parent": "row-1", "width": "half" }
] }
```

## Шаги

### L0 — контракты и формат (поведение не меняется)

- `FormItemKind`, `FormItem.Parent/Kind`, `FormItemWidths.Quarter`; `FormLayoutJson` пишет/читает
  новые поля, старый плоский и до-R3 вложенный формат читает в новые узлы (`sectionTitle` →
  `Heading`).
- `FormItem.IsSectionHeader` уходит (роль берёт `Kind`); поиск потребителей — по grep.

Проверка: `FormLayoutJsonTests` (старый плоский, до-R3 вложенный, новый, round-trip),
`PostTypeOptionsCatalogTests`, `UpdatePostTypePresentationTests`.

### L1 — нормализатор и проектор

- `FormDefinitionNormalizer` — проверка матрицы родителей (недопустимый родитель → в корень зоны),
  дедуп по ключу, неизвестные поля провайдера дописываются в корень своей зоны, идемпотентность.
  Неполевые узлы (`Heading`/`Divider`/структурные) в дефолтах не ищутся.
- `FormLayoutTree.From(items, zone)` — сборка дерева (группировка по `Parent`, порядок = порядок
  в массиве) + обратная упаковка для дизайнера.

Проверка: `FormDefinitionNormalizerTests`, новый `FormLayoutTreeTests`; `PostFormBuilderTests`.

### L2 — рендерер

- `FormRenderer` → рекурсивный `FormLayoutNodeView` (Row/Column/Field/Heading/Divider/Container);
  `WidthClass` учит `quarter`; пустая колонка рендерится.
- `PostFormZone`, `FormContextOf`, зоны в `EditPostView` — без изменений.

Проверка: сборка + E2E формы поста (существующие раскладки выглядят как раньше).

### L3 — модель дизайнера (без Blazor, под тестами)

- `FormLayoutDraft` (в `Mars.Admin.Framework`): плоский черновик + операции — добавить/удалить
  контейнер, ряд, колонку, заголовок, разделитель; положить поле в узел; сменить `Parent`
  (перемещение с сохранением поддерева); сменить ширину; «переподвесить» детей при удалении узла
  (в родителя) — плюс список неразмещённых полей типа (палитра).
- Дизайнер перестаёт собирать `FormLayoutSettings` вручную из строк — этим занимается черновик.

Проверка: новые тесты в `Mars.Admin.Framework.Tests` (перемещения, удаление с переподвеской,
пустые колонки, легаси-раскладка).

### L4 — компонент дизайнера на Drag/Drop

- `FluentDragContainer<T>` + `FluentDropZone<T>` с `StopPropagation="true"` для каждого уровня
  (в 4.14.4 `FluentDragItem`/`FluentDragItemsGroup` нет — вложенный пример из доков собран на этой
  паре; песочница — `devstands/TestModules/Pages/FormsBuilderPage.razor`).
- Табы контейнеров, пустые слоты как дропзоны, палитра неразмещённых полей, inline-кнопки
  (удалить, ширина) — без flyout/контекстных меню.
- Контракт компонента (`Definition`, `ValueChanged`, `OnResetRequested`) сохраняем: хосты —
  `EditPostTypePresentationPage` и `PostFormLayoutDialog` — не меняются.

Проверка: сборка; визуальная проверка в запущенном приложении; тесты черновика из L3.

### L5 — E2E и приёмка

- E2E: раскладка с двумя контейнерами, рядом и пустой колонкой (задаётся через API) — рендер
  табов, значений и сохранение поста. Существующие `CreatePostTests`, `EditPostMetaFieldsTests`,
  `EditPostRelationFieldTests`, `EditPostSystemFieldEditorTests`, `EditUserPageTests` — зелёные.
- Ручная проверка drag&drop в браузере (Playwright-drag для дизайнера не автоматизируем).

Проверка: `dotnet build Mars.slnx`; `Mars.Forms.Tests`; `Mars.Admin.Framework.Tests`;
`Mars.Server.Tests`; интеграционные `Controllers.PostTypes`; E2E (`MARS_E2E_TESTS=1`, рецепт —
в FormEngineSimplifyPlan.md).

## Решённые по ходу развилки

- Контейнеры разрешены в любой зоне, включая узкие сайдбары (`publish`/`extra`): табы там
  прокручиваются.
- Палитра неразмещённых полей — карточка «Поля типа вне раскладки» над зонами; поле
  возвращается в свою зону по умолчанию.
- План живёт отдельным файлом, ссылка — в конце `FormEngineSimplifyPlan.md`.

Что получилось по факту; расхождения с планом сознательные:

- **Нормализатор порядко-независим**: родитель находится по ключу, а не по позиции в списке
  (дизайнер умеет поставить ребёнка перед родителем), циклы и потерянные родители разрываются
  в корень зоны. Узел, которому не место даже в корне зоны (колонка), отбрасывается, а его дети
  переезжают в корень следом.
- **Перенос адресуется «перед узлом»**, а не индексом (`Move(key, parent, beforeKey)`): узел —
  сам цель броска, поэтому индекс не нужен и пропадает класс ошибок «сдвиг на единицу».
- **Дизайнер читает раскладку тем же проектором** `FormLayoutTree`, что и рендер формы.
- **Узлы вне контейнеров** (легаси-раскладка) видны и переносимы: в зоне с контейнерами под
  табами есть область корня зоны.
- **Секции** убраны, вместо них узлы `Heading`/`Divider`; легаси `sectionTitle` читается
  как заголовок.
- **Натуральная ширина (`auto`)** не делалась, как и планировалось: `null` = full.
- **Вид ячеек дизайнера** (по замечаниям пользователя): элемент — прямоугольник с названием и
  иконками (глаз — видимость, корзина — убрать), без инпута заголовка и чекбокса; ширина числом
  (12/6/4/3) — только у ячейки-колонки; у ряда сплошная акцентная рамка, у ячейки — пунктирная
  нейтральная.
- **Уточнение 2026-09-12 (второй заход по замечаниям): элементы — только в колонках.** Матрица
  правил запрещает элементу (поле, заголовок, разделитель) ряд и зону; нормализатор оборачивает
  свободные элементы в ряд с колонками, ширина элемента переезжает на колонку, а идущие подряд
  элементы складываются в один ряд, пока сумма долей ≤ 12 (как их разложил бы бутстрап) — легаси
  раскладки «плоским списком» продолжают выглядеть как раньше. В дизайнере зона и контейнер —
  вертикальный список рядов, ряд — колонки ровно по размеру (флекс-слой без `gap`, отступы
  внутренней рамкой), колонка — вертикальный список элементов и вложенных рядов; в корне зоны
  и в контейнере кнопка только «Ряд», в ряду — «Колонка», в колонке — «Ряд/Заголовок/Разделитель».

- **Уточнение 2026-09-12 (третий заход по замечаниям): раскладка по умолчанию — «одна строка и
  одна колонка на зону».** Нормализатор больше не набивает ряд до 12 долей: свободные элементы
  родителя (зоны, контейнера) складываются в **один** ряд, а внутри него соседи без своей ширины
  живут в общей колонке — элемент с шириной получает свою. Легаси-плоская раскладка, где ширину
  задавал элемент, даёт те же классы (бутстрап сам переносит `col-*` на новую строку), а раскладка
  без ширин — ровно одну строку с одной колонкой. Ключ группировки — «родитель + зона»: корневые
  узлы разных зон неродственны. В дизайнере «ряд» называется **строкой**, надпись строки стоит
  слева от колонок (а не над ними), селект ширины колонки — 50px.

## Гардайлы

- Внешний вид и поведение форм без сохранённой раскладки не меняются: легаси-элементы дают те же
  классы `col-12` / `col-12 col-md-6` / `col-12 col-md-4`, легаси-ширина переезжает на колонку.
- Ключи полей (`title`, `slug`, …) — стабильные идентификаторы, на них завязаны E2E-селекторы.
- Ядро значений, редакторы, реестры панелей/редакторов и метаполя этот план не трогает.
- Верификация точечная по затронутым областям + полная сборка `dotnet build Mars.slnx`.
