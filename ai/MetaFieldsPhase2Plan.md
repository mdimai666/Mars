## Контекст

Хранение и модель мета-полей переработаны (плоские поля, таблицы значений на семью,
1:N-владение, ключи вариантов, статусы-таблица, мульти-значения Relation, Query-поля,
views по требованию). Следующий пласт — удобство работы в админке и поведение полей:
отображение списков постов, правила валидации, автогенерация значений, настраиваемые
редакторы значений.

Текущее состояние (исследование 2026-08-23):
- список постов типа — `AppAdmin/Pages/PostsViews/ManagePostView.razor`: FluentDataGrid
  с фиксированными колонками (Title, Categories, Tags, Status, Author, CreatedAt),
  серверная сортировка/пагинация;
- `PostTypePresentationEntity` — 1:1 таблица с типом (`PostTypeId` PK, пока только
  `ListViewTemplateSourceUri`), есть эндпоинты `GetPresentationEditModel`/`UpdatePresentation`
  и страница `EditPostTypePresentationPage`;
- у поля уже есть `Options` jsonb (точка расширения), `IsNullable`, `MinValue`/`MaxValue`;
- реестровый паттерн для расширяемых списков уже обкатан на целях Relation
  (keyed-сервисы `IMetaRelationModelProviderHandler`).

## Принятые решения (2026-08-23)

1. **Грид — первой версией без фильтров.** Колонки + сортировка + пагинация; фильтры —
   вторым шагом (Фаза Д, детали отдельно).
2. **Настройки грида — в `PostTypePresentationEntity`** (сущность задумывалась про
   отображение в админке). Форма: упорядоченный список видимых колонок (ключи базовых
   колонок — `title`, `slug`, `status`, `created_at`, `modified_at`, `author` — и ключи
   мета-полей) + колонка и направление сортировки по умолчанию. Хранение — новая
   колонка в стиле `Options` (jsonb), типизированные колонки не плодить.
3. **Настройка колонок доступна в обоих местах**: кнопка «Настроить колонки» прямо на
   гриде (`ManagePostView`, диалог) и та же настройка на странице
   `EditPostTypePresentationPage` — общий компонент.
4. **Данные грида**: базовые колонки из `posts`, мета-колонки через view
   (`PostTypeViewService.ListFromViewAsync` — добавить сортировку и пагинацию).
5. **Валидация — реестр расширяемых валидаторов.** Правила в `Options.validators`
   (массив `{ type, params }`). Обязательность — существующий `IsNullable`, диапазон —
   существующие `MinValue`/`MaxValue` (новыми валидаторами не дублировать). Первая
   волна реестра: регулярное выражение (паттерн + сообщение), длина строки (мин/макс).
   Проверка: сервером при записи значений (общий путь для JSON-API и админки) и
   фронтендом в формах редактирования значений.
6. **Генераторы — реестр, в `Options.generator`** (`{ type, params }`). Первая волна:
   - `sequence` — номер очереди: шаблон = литеральный префикс + число с паддингом
     (пример: `ВУ0002`); режимы счётчика: «продолжается» и «сброс каждый день»;
     префикс из категории — **словарь категория→префикс** в параметрах генератора;
   - `текущая дата/время` — автозаполнение моментом создания.
   Состояние счётчиков — новая таблица (условно `mt_sequences`: `meta_field_id` +
   скоуп (день/категория) → `last_value`), атомарный инкремент в транзакции создания
   поста. Остальные генераторы добавляем по мере потребности.
7. **Редакторы значений — реестр** (ключ → компонент + список совместимых типов поля).
   Выбор редактора поля хранится в `Options.editor`; пусто = дефолтный редактор типа.
   Первая волна: `Цвет` для String, `Url`, `Email`, варианты `дата`/`время` для DateTime.
   Расширение списка — позже через фронт-плагины.
8. **Пикер типа поля — человеческие пресеты.** Выбор типа замешивается с пресетами:
   «человеческие» типы (Текст, Длинный текст, Число, Дата, Да/Нет, Выбор из списка,
   Цвет, Ссылка, Email, Файл, Изображение, Связь) + одно подменю «Технические»
   (`Int`, `Long`, `Float`, `Decimal`, `SelectMany`, `Query`, …). Пресет = тип +
   редактор (+ валидаторы), после применения редактируется как обычный набор настроек.
   Реализация пресетов — фронтенд (список в админке), без миграций.
9. **Конвенции**: внешние ключи новых сущностей — только во fluent-конфигурациях;
   новые настройки в существующих jsonb — без миграций; миграции только для новых
   колонок/таблиц (настройки грида, `mt_sequences`).

## Фазы

- **Фаза А — грид.** Миграция: колонка настроек грида в `post_type_presentations`.
  DTO/эндпоинты презентации расширяются настройкой колонок. `ListFromViewAsync` +=
  сортировка и пагинация. `ManagePostView` строит колонки динамически из настройки
  типа. Диалог «Настроить колонки» на гриде + тот же компонент на
  `EditPostTypePresentationPage`.
- **Фаза Б — валидаторы.** Реестр валидаторов (паттерн целей Relation), чтение
  `Options.validators`, первая волна: регулярка, длина строки. Серверная проверка при
  записи значений (общий путь), ошибки — в ответ записи. Фронтенд-валидация форм
  значений тем же списком.
- **Фаза В — генераторы.** Миграция `mt_sequences`. Реестр генераторов, `sequence`
  (шаблон, режимы сброса, словарь категория→префикс, атомарный инкремент) и
  `текущая дата/время`. Вызов при создании поста (общий путь записи значений).
  Редактор параметров генератора в настройках поля.
- **Фаза Г — редакторы и пресеты.** Реестр редакторов, `Options.editor`, первая волна
  редакторов (Цвет/Url/Email/дата-время), переключение редактора в формах значений.
  Пикер типа поля: пресеты + подменю «Технические».
- **Фаза Д — фильтры грида** (второй шаг, детали отдельно): по типам колонок —
  поиск по тексту, сравнение чисел/дат, выбор варианта, «заполнено/пусто».
- **Фаза Е — вычислимые Query-поля, второй пласт** (после А–Д, дизайн обсудить
  отдельно до реализации): определение поля как текст запроса (QueryLang/linq) с
  опорой на `this` — вместо нынешнего пресета «обратная ссылка» (пресет становится
  генератором такого текста); резолв батчем на чтении существующим механизмом;
  редактор запроса (подсветка/автодополнение) — отдельно и позже; отображение
  вычислимых колонок в гриде — после базовых фаз.

Порядок Б/В/Г может уточняться — они слабо связаны между собой; Фаза А — первая
(самый видимый результат, использует готовые views). Фаза Е — после А–Д.

## Верификация (правило: точечно, не весь сьют)

Общий build `Mars.slnx`; по каждой фазе — только затронутые тесты:
- юнит: `Test.Mars.Host` (валидаторы, генераторы, настройка грида/`ListFromViewAsync`);

## Вне скоупа

- фильтры грида — Фаза Д, отдельное обсуждение;
- linq-редактор Query-полей и инлайн-редакторы объектов — следующие шаги;
- расширяемые реестры валидаторов/генераторов/редакторов из плагинов — первая волна
  встроенная, плагинное расширение по появлении потребителя;
- уникальность значения как валидатор — позже (требует проверки в БД).
