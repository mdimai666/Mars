# План мета-полей — Фаза 7: файлы без постов, множественность, карточки детей

> **Статус: реализация выполнена 2026-08-25 (миграция `20260824224102_MetaFieldIsMultiple`),
> ждёт обкатки пользователем, без коммита.** Ветка `ai/metafields-rework`.
> Одна миграция (колонка на `meta_fields`) + контракты;
> остальные настройки — в существующем `Options` полей. Продолжение
> `ai/MetaFieldsPhase6Plan.md` (Single-тип выполнен) и
> `ai/MetaFieldsPhase3Plan.md` (вне скоупа: «режим карточек в секциях
> детей — следующий этап»). Исследование индустрии 2026-08-25 (проверено
> по докам): «дроп файлов» в продуктах — две модели: файл = запись с полями
> (вложения WordPress, Payload upload-коллекции) и файл = ассет-значение
> (Strapi media single/multiple, Sanity image-массивы, ACF Gallery как
> набор вложений). Обе модели у нас уже есть как примитивы — фаза приводит
> в порядок их поведение и отображение.

## Контекст

Разведка 2026-08-25 (состояние после Фазы 6):
- **дроп в секции детей** (`MetaValueChildrenList`): зона показывается, только
  если у детского типа есть приёмник — `ResolveDropField`: указатель картинки
  типа (`ImageFieldKey`) → первое поле Image → первое поле File; на каждый файл
  создаётся пост-ребёнок (заголовок = имя файла, слаг + guid-суффикс, одно
  значение с `ModelId` файла в поле-приёмник) и привязывается к родителю.
  Сценарий «раздел документов» (скопом закинуть файлы → посты с файлами)
  **уже работает**, работ не требует;
- **одинарные Файл/Изображение** в форме — `FSelectMedia`: плитка 102x102,
  превью запрашивается отдельно на каждую плитку (`service.Get(id)` с лоадером;
  серверный батч в ответ редактирования отклонён пользователем — оставить как
  есть), выбор через медиа-пикер, картинки кликабельны в полный размер
  (`Image2` с `PreviewSrc`), для не-картинок просмотра нет; **дропа нет**;
- **мульти-значения** сервер поддерживает для всех типов (строки `{ModelId,
  Index}`, JSON — массивы, `PostDetailResponse.MetaValues` = «ключ → список»,
  клиентская модель `MetaValuesByIndex` = `(Key, Index)`), но форма для
  не-Relation берёт только `Index == 0`;
- **Relation без `kind=list` всегда множественный** (`MetaValueRelationMulti`:
  строки с заголовками, драг-порядок, пикер с мультивыбором); одинарной связи
  не существует;
- **медиа-пикер** `ModalMediaSelect` — строго одиночный выбор
  (`IAppMediaService.OpenSelectMedia`, ~15 потребителей по кодовой базе);
- `Options`-ключи поля живут в `MetaFieldKindCatalog`: `kind` (пока единственное
  значение `list`), `removeMode`, `uploadFolder`; пресеты пикера —
  `MetaFieldTypePresets` («Список объектов» = Relation + kind=list);
- на `MetaFieldEntity` уже есть флаг-ограничение значения `IsNullable` —
  конвенция `Is*` для парного флага кратности;
- превью детских постов уже батчатся сервером (`PostMetaColumnsService` /
  `ImagePreviewResolver`), таблица детей уже рендерит миниатюры в Image-колонках;
- `MediaUploadZone` переиспользуется (авто-режим загрузки с `FolderPath`;
  грабля `FluentInputFile.OnInputFileChange` — в авто-режиме делегат не задавать).

## Принятые решения (2026-08-25)

1. **Две модели дропа — по примитивам.** «Файл = запись с полями» — поле-список
   (Relation + `kind=list`): дроп создаёт пост-ребёнка на каждый файл (как есть).
   «Файл = значение» — поля Файл/Изображение: дроп загружает файл в медиа и
   ставит значением, **без постов**. Граница: файлу нужны свои поля (подпись,
   автор…) — это детский тип. Пер-элементные атрибуты значения (подпись без
   детского типа) — отклонены, граница держится.
2. **Кратность и режим работы — две разные оси.** Кратность — свойство модели
   данных: **колонка `IsMultiple` на `MetaFieldEntity`** (миграция: `is_multiple`
   bool not null default false), пара к существующей `IsNullable`. Дефолт нового
   поля — **одинарный**; бэкфилла нет: существующие Relation-поля станут
   одинарными (смена принята пользователем). Режим работы/редактора остаётся в
   `Options.kind` со значением `list` (секция детей) — серверу `kind` не нужен,
   в колонку не переезжает.
3. **`kind` и `IsMultiple` связаны**: `list` доступен только множественному
   Relation (валидаторы типов). Форма: тумблер «Несколько значений» — для
   Relation/Файл/Изображение (у скалярных типов не показывается); селект `kind`
   (обычный / «Список объектов») показывается только при включённом тумблере;
   выключение тумблера при `kind=list` очищает `kind` (клиентская синхронизация
   по прецеденту сброса несовместимого редактора при смене типа поля).
4. **Редакторы по матрице** (тип + `IsMultiple` + `kind`):
   - Файл/Изображение одинарные: `FSelectMedia` + дроп на плитку (загрузка без
     поста, папка — `Options.uploadFolder` поля) + просмотр в полном размере
     (картинки умеют; не-картинкам — кнопка «открыть» по `FileUrl`); разметку
     плитки причесать (мёртвые ветки, пустая кнопка-очистка);
   - Файл/Изображение множественные: новый `MetaValueFileMulti` — плитки с
     превью (каждая запрашивает сама, как `FSelectMedia`), драг-порядок
     (`FluentSortableList`), добавление дроп-зоной и мультивыбором из медиа,
     удаление = отвязка (файл остаётся в медиа), переиндексация строк;
   - Relation одинарный: новый компактный редактор — выбранный объект
     (заголовок + миниатюра из `GetMetaValueRelationModels`) + пикер в
     одиночном режиме + очистка;
   - Relation множественный: `MetaValueRelationMulti` без изменений;
   - Relation `kind=list`: секция детей (таблица/карточки — п. 6).
5. **Мультивыбор в медиа-пикере**: `ModalMediaSelect` получает режим с
   чекбоксами и кнопкой «Добавить выбранные» (паттерн
   `MetaValueRelationSelectDialog.MultiSelect`); `IAppMediaService` += метод
   мультивыбора; существующие одиночные вызовы не трогаются.
6. **Видимость дроп-зоны — ключ `Options.dropZone`** (bool, отсутствие = true):
   дефолт включена везде, где применимо; выключается в форме поля. Читается в
   редакторах п. 4 и в секции детей.
7. **Карточки для списков детей**: ключ `Options.viewMode` на поле с
   `kind=list`: `table` (дефолт) / `cards`. Карточка = превью по `ImageFieldKey`
   детского типа (данные уже отдаёт `PostMetaColumnsService`) + заголовок;
   клик — существующий drawer-редактор; порядок — драгом в `Index`; удаление —
   по `removeMode`. Дроп-зона в режиме карточек остаётся полосой (плитка «+» —
   позже, опционально).
8. **Пресеты пикера**: «Связь» — одинарная; новые пресеты — «Несколько связей»
   (Relation + `IsMultiple`), «Набор изображений» (Изображение + `IsMultiple`);
   «Список объектов» выставляет `IsMultiple` + `kind=list`. Структуре пресета
   добавить флаг кратности. «Файл» + множественность — через тумблер, отдельный
   пресет не нужен.
9. **Бланки**: для множественных полей бланк = ноль строк значений
   (сейчас бланк-билдер материализует строку на каждое поле — поправить);
   для одинарных — одна пустая строка, как сейчас.
10. **Серверные правила кратности** (в общем пути валидации значений, админка +
    JSON-запись): одинарным полям (`IsMultiple=false`) значения с `Index>0`
    отклоняются. Проверка по колонке, без парсинга `Options`. Хранение и форма
    контрактов значений не меняются: и «один», и «много» — одна строка или
    N строк с `Index`; публичные ответы остаются массивами.
11. **Конвенции**: внешние ключи новых настроек — стабильные строковые (под
    будущую мультиязычность); `Options` — только про отображение/поведение
    редакторов; свойства модели данных — типизированные колонки.

## Шаги реализации

1. **Колонка и контракты.** Миграция: `is_multiple` на `meta_fields` (bool not
   null default false). `MetaFieldEntity.IsMultiple`; контракты полей
   (`MetaFieldDetailResponse`, реквест сохранения полей) + клиентская
   `MetaFieldEditModel.IsMultiple`. Валидаторы типов
   (`Create/UpdatePostTypeQueryValidator`): `kind=list` только для Relation с
   `IsMultiple` и целью `Post.<тип>`. Правило п. 10 в валидации значений.
   Бланк-билдер: множественные поля — ноль строк (п. 9).
2. **Форма поля и пресеты.** Тумблер «Несколько значений» (только
   Relation/Файл/Изображение), селект `kind` при включённом тумблере для
   Relation, очистка `kind` при выключении; флаг кратности в
   `MetaFieldTypePresets` + пресеты п. 8; селект `dropZone`.
3. **Медиа-мультивыбор.** Режим мультивыбора `ModalMediaSelect` + метод в
   `IAppMediaService`; одиночный путь без изменений.
4. **Редакторы.** `MetaValueFileMulti` (плитки/драг/дроп/пикер/отвязка);
   одинарный редактор Relation (по форме близнец `FSelectMedia`: тайл с
   выбранным объектом, пикер в одиночном режиме, очистка); ветвление
   `FormMetaValueItems` по `IsMultiple`/`kind` для Relation/Файл/Изображение.
5. **Файлы без постов.** Дроп на плитку `FSelectMedia` (загрузка через
   `MediaUploadZone` → значение без поста), кнопка «открыть» для не-картинок,
   чистка разметки плитки; дроп-зона в `MetaValueFileMulti`.
6. **Карточки детей.** Ветка `viewMode=cards` в `MetaValueChildrenList`
   (карточка = превью + заголовок, клик — drawer, драг-порядок, удаление по
   `removeMode`); чтение `dropZone`/`viewMode` в секции детей.

Шаг 1 — фундамент; 2–6 слабо связаны, порядок свободный.

## Верификация (правило: точечно, не весь сьют)

Общий build `Mars.slnx`.
- Юнит `Test.Mars.Host`: валидаторы типов (запрет `kind=list` для
  не-множественного/не-Relation), правило `Index>0` для одинарных полей,
  бланки множественных полей без строк.
- Интеграционные точечно: типы постов (ограничения `kind`/`IsMultiple`),
  запись значений (`Index>0` для одинарного поля → 400).
- Контракты `WebApiClient` **обязательно** (ответ полей получает новое поле) —
  прогон клиента типов постов.
- Редакторы, дроп, карточки — визуально при разработке, отдельным прогоном
  не проверять.

## Вне скоупа

- серверный батч-резолв превью в ответ редактирования (отклонён 2026-08-25:
  плитки запрашивают файл сами, как сейчас);
- бэкфилл существующих Relation-полей в множественные (дефолт `IsMultiple=false`
  принят как смена поведения);
- пер-элементные атрибуты файлов (подпись/альт без детского типа);
- переезд `kind` в колонку (нужен только фронту; если понадобится серверу —
  одной миграцией);
- ветвление Mto/генераторов по `IsMultiple` (одинарная навигация против
  коллекции) — с приходом упрощения генераторов.
