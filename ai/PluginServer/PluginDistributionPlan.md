# Распространение плагинов Mars — исследование и план

> Исходный брейншторм: [PlanPluginServerPrompt.md](PlanPluginServerPrompt.md)
> Дата: 2026-08-11

Цели (из брейншторма):
- показывать рейтинги и отзывы;
- маркировать рекомендованные плагины;
- банить вредоносные или сильно зарепортенные;
- в будущем — галерея рецептов и скиллов (JSON-файлы).

## Ключевой принцип, к которому приходят все экосистемы

**Разделять каталог (метаданные) и хостинг (бинарники).** Рейтинги, отзывы, «рекомендовано», баны — это всегда своя небольшая служба с БД. А вот хранение и отдачу файлов почти все делегируют готовой инфраструктуре (npm, nuget.org, GitHub Releases). Полный маркетплейс «с нуля» никто не строит.

## Как это делают другие

| Платформа | Модель | Рейтинги | Модерация |
|---|---|---|---|
| WordPress.org | свой репозиторий, обязательный ревью при первой подаче | да | да, «Featured», закрытие уязвимых плагинов |
| VS Code | свой registry; есть open-source аналог **Open VSX** (EPL-2.0, self-host) | да | верификация publisher'ов |
| n8n | ноды = npm-пакеты, поиск по npm; есть **verified**-панель и **blocklist** вредоносных | нет | blocklist + verified-уровень |
| Obsidian | центральный JSON-манифест в GitHub-репо, подача через PR + ручное ревью; файлы — из GitHub Releases автора | нет (кол-во загрузок) | ревью PR |
| Home Assistant (HACS) | манифесты в репо, загрузка из GitHub Releases, авто-валидация через Actions | нет | автоматическая |
| Node-RED Flow Library | свой сайт-каталог, сами ноды — npm-пакеты | «лайки» | подача с ревью |
| Grafana | свой каталог, подача через PR, **подпись плагинов** | нет | подпись кода |
| winget / Chocolatey | манифесты в GitHub + PR + CI-валидация; у Chocolatey — модерация и антивирус-сканирование | нет | авто-валидация + модераторы |

## Оценка исходных вариантов

### Вариант 1 — обычный nuget.org + маркировка

Сильный, проверен на практике. Поисковый API nuget.org поддерживает фильтр `packageType`
(живой запрос `https://azuresearch-usnc.nuget.org/query?q=...&packageType=Template` вернул
отфильтрованный список с `totalDownloads`, тегами и URL иконки).
Достаточно в nuspec `<packageType>MarsPlugin</packageType>` — и получается чистый фильтр без
спама тегами, бесплатные версии, статистика загрузок и резолв зависимостей стандартным
NuGet.Protocol. Плюс nuget.org умеет **prefix reservation** (защита неймспейса `Mars.*` от
тирсквоттинга). Минус один — нет рейтингов/отзывов; решается вариантом 1.1.

### Вариант 1.1 — свой список + хостинг на nuget.org (оптимум для старта)

Это и есть модель n8n / Grafana / Node-RED: бинарники на nuget.org, а каталог со
статусами / рейтингами / банами — свой маленький сервис.

### Вариант 2 — свой NuGet-сервер (преждевременен как первый шаг)

Технически всё решено: **BaGet** (MIT, .NET, Docker, активен) умеет read-through-кеширование /
зеркалирование nuget.org — проблема «общие нугеты тянуть из основного репо» закрывается прокси.
Но это операционная нагрузка (хостинг, аптайм, хранилище, бэкапы), а рейтингов он всё равно
не даёт. Оправдан позже для: приватных/enterprise-плагинов, WordPress-модели «публикация
только после ревью», полного контроля.

### Вариант 3 — GitHub Releases (модель Obsidian/HACS)

Бесплатно, PR-ревью, децентрализация. Но нет единого API поиска/версий/зависимостей,
фрагментация. Как основной канал — слабоват; как **дополнительный** источник
«community»-плагинов и как хостинг для рецептов/скиллов — отлично.

Важно: **GitHub Packages для NuGet не годится** — даже публичные пакеты требуют токен
на скачивание.

### Вариант 4 — готовое решение

Готового маркетплейса «с рейтингами для .NET-плагинов» не существует: Open VSX — open-source,
но жёстко заточен под VS Code-расширения, переделка дороже своей службы. Готовы только
строительные блоки (BaGet, Sleet для статического фида, Azure Artifacts, Cloudsmith),
а каталог все делают сами — он небольшой.

## Рекомендуемая архитектура (фазы)

**Фаза 0 — конвенции пакетов**
- `<packageType>MarsPlugin</packageType>` в nuspec, теги;
- метаданные совместимости (мин./макс. версия Mars);
- prefix reservation `Mars.*` на nuget.org.

**Фаза 1 — каталог-сервис**
- сущности: Plugin (↔ NuGet id), статус (none / recommended / banned), Rating, Review, Report;
- админка: витрина + overlay статусов, установка через NuGet.Protocol с nuget.org;
- вариант реализации — догфудинг: каталог как инстанс самого Mars с PostTypes
  «Plugin» / «Review» (дёшево + демонстрация CMS-возможностей платформы).

**Фаза 2 — модерация**
- кнопка «пожаловаться» → очередь модерации; бан по порогу жалоб (аналог blocklist n8n);
- «рекомендовано» только после ручного ревью и/или проверки подписи пакета
  (NuGet поддерживает signed packages).

**Фаза 3 (опционально) — свой фид**
- BaGet с зеркалированием nuget.org как *дополнительный* источник;
- клиент поддерживает N источников (модель apt / Helm-репозиториев);
- для приватных плагинов и полного контроля.

**Рецепты и скиллы** — тот же каталог, отдельный тип сущности. Это просто JSON — NuGet им
не нужен: git-репо с манифестом, установка скачиванием файлов. Можно запустить даже раньше
плагинной части.

## Точка старта в текущем коде Mars

- ZIP-загрузка уже работает (`PluginController.UploadPlugin` → `PluginZipInstaller`),
  но `InstallPlugin` — заглушка «not implemented».
- Метаданные уже читаются из атрибутов сборки: `PackageId`, `PackageTags`, `RepositoryUrl`,
  `PackageIcon` (`PluginManager.cs`) — конвенция наполовину готова.
- Есть неиспользуемый `src/Plugin/Mars.Plugin/NuspecHelper.cs` (генерация/парсинг nuspec
  с зависимостями) — готовый задел.
- Плагины грузятся только при старте (`Assembly.LoadFrom`, без ALC) — маркетплейсу
  понадобится либо установка «применить после рестарта», либо горячая догрузка.
- Чего нет: установки через NuGet.Protocol, конфигурации источников, клиента каталога.

## Риски

- **Безопасность:** плагин .NET — произвольный код, изоляции нет (ALC — не security-граница).
  Модерация, подписи и установка только с подтверждения админа — обязательная часть.
- **Тирсквоттинг:** prefix reservation + verified-паблишеры на nuget.org.
- **Совместимость:** версия Mars как ограничение в метаданных плагина.

## Итог одной строкой

Вариант **1.1 как основа** (каталог свой, хостинг nuget.org), BaGet — на фазе 3 для
контроля/приватных плагинов, GitHub Releases — для рецептов/скиллов и как дополнительный
источник.
