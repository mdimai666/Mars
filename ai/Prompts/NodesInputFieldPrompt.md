# Expression Value Input для Mars Node Code CMS

## Цель

Создать компактный однострочный input для ввода значений в нодах визуального программирования Mars.

Поле должно быть дружелюбным для обычного пользователя, но поддерживать выражения, ссылки на данные и типизированные константы. По умолчанию это обычное поле ввода, которое постепенно раскрывает дополнительные возможности по мере необходимости.

Пользователь должен иметь возможность вводить значения вручную или выбирать их из доступного контекста через дерево объектов.

## 1. Основные режимы

### Обычная строка

Если пользователь вводит обычный текст без специального префикса, это строковая константа.

```text
Some name
```

### Выражение

Символ `@` в начале переключает поле в режим выражения.

```text
@msg.payload.age
```

```text
@msg.payload.age + 2
```

`@` является только переключателем режима и не используется перед каждым отдельным источником.

Например:

```text
@msg.payload.age + msg.user.age
```

Корректно.

```text
@msg.payload.age + @msg.user.age
```

Не требуется поддерживать.

Выражения должны быть максимально близки к C# по синтаксису и именованию методов:

```text
@msg.user.firstname.ToUpper()
@msg.payload.name.Substring(0, 5)
```

На первом этапе достаточно поддержки обращений к свойствам, констант, арифметических операций и простых методов преобразования строк.

### Типизированная константа

Пользователь может выбрать тип значения через кнопку в поле.

Например, выбор `DateTime` открывает date picker.

После выбора типа поле становится редактором соответствующей константы.

```text
2026-09-16
```

Типизированная константа не должна поддерживать выражения в этом режиме.

При этом пользователь должен иметь возможность вернуть поле из режима константы в обычный режим ввода или выражения.

## 2. Поведение при вводе

Поле должно оставаться обычным текстовым input.

Необходимо поддержать:

* Ввод обычного текста.
* Ввод `@` в начале строки.
* Подсказки после точки.
* Вызов подсказок через `Ctrl+Space`.
* Ручной ввод выражений.
* Выбор свойств из дерева.
* Вставку выбранного свойства в текущую позицию курсора.
* Определение режима поля по введённому значению.
* Возможность вручную переключить режим.

Пользователь не обязан выбирать тип перед вводом.

Если он начинает с `@`, поле переходит в режим выражения.

Если он вводит обычный текст, поле остаётся строкой.

Если пользователь выбирает тип константы, поле переходит в соответствующий редактор.

## 3. Автодополнение

Автодополнение должно быть контекстным и работать по доступным данным.

Пример:

```text
@msg.
```

Показывает свойства объекта `msg`.

```text
payload       object
user          User
topic         string
timestamp     DateTime
```

После выбора:

```text
@msg.payload.
```

Показываются свойства `payload`.

Подсказки должны учитывать тип текущего объекта.

Вызов подсказок:

* После ввода точки.
* Через `Ctrl+Space`.
* При необходимости через кнопку выбора источника.

Не требуется реализовывать полноценный IntelliSense уровня Visual Studio.

Необходимо поддержать только доступные объекты, свойства и базовые операции, предусмотренные языком выражений Mars.

## 4. Кнопки и визуальный интерфейс

Поле должно быть компактным и однострочным.

Предлагаемая структура:

```text
┌─────────────────────────────────────────────┐
│ @msg.payload.age + 2                    ◈ │
└─────────────────────────────────────────────┘
```

Справа — кнопка выбора значения из контекста.

Дополнительная кнопка `[ƒ]` появляется, когда поле находится в режиме выражения.

Она открывает список доступных операций и преобразований.

Например:

* String operations.
* Math operations.
* Convert.
* Date operations.

На первом этапе не требуется сложный визуальный конструктор выражений.

Редактор должен быть ориентирован на ввод с клавиатуры.

## 5. Подсветка выражений

Необходимо предусмотреть визуальную подсветку частей выражения.

Например:

```text
@msg.payload.age + 2
```

Ссылка `msg.payload.age` должна визуально отличаться от оператора `+` и константы `2`.

На первом этапе не требуется полноценный редактор с chip-блоками.

Необходимо сохранить обычный текстовый ввод.

В дальнейшем можно добавить интерактивный выбор свойств при клике по пути.

## 6. Выбор свойств из дерева

Правая кнопка открывает дерево доступных объектов и свойств.

Пример:

```text
msg
├── payload
│   ├── age       number
│   └── name      string
├── user
│   └── firstname string
└── topic         string

flow
└── counter       number

global
└── var1          string
```

При выборе свойства оно вставляется в текущую позицию курсора.

Например:

```text
@msg.payload.age + 2
```

При выборе `msg.flow.counter` в конце выражения:

```text
@msg.payload.age + 2 + msg.flow.counter
```

Дерево должно предоставлять информацию о типах свойств.

## 7. Ожидаемый тип

Поле должно быть generic-компонентом.

Например:

```csharp
<MarsValueInput T="int" />
```

Ожидаемый тип определяет тип результата значения.

При этом generic не должен ограничивать возможности языка выражений.

Пользователь может использовать преобразования и промежуточные значения, чтобы получить нужный результат.

Например:

```text
@msg.payload.age.ToString().Length
```

Если ожидаемый тип — `int`, выражение допустимо.

## 8. Возможность отключить выражения

При объявлении поля должна быть возможность указать, разрешены ли выражения.

Например:

```csharp
<MarsValueInput T="string"
                AllowExpression="true" />
```

По умолчанию выражения разрешены.

Если выражения отключены, поле должно работать только как редактор констант.

Это позволит использовать тот же контрол в разных местах CMS.

## 9. Ошибки

Необходимо разделить ошибки синтаксиса и ошибки типа.

Синтаксические ошибки должны показываться сразу.

Например:

```text
@msg.payload.age +
```

Ошибки типов также должны показываться пользователю.

Например:

```text
@msg.payload.name + 2
```

Если `name` — строка, а ожидаемый результат — число.

При этом выражение не обязательно запрещать сохранять: некоторые типы данных могут быть динамическими и проверяться только во время выполнения.

## 10. Ограничения первой версии

Не нужно сразу реализовывать:

* Полноценный AST-редактор.
* Chip-блоки.
* Drag & drop.
* Сложный визуальный конструктор выражений.
* Полноценный C# IntelliSense.
* Полную поддержку всех методов .NET.
* Сложные вложенные редакторы.

Первая версия должна быть простой, компактной и удобной для ввода.

## 11. Что необходимо подготовить перед реализацией

Перед написанием кода изучить существующую архитектуру Mars Node Code CMS и определить:

1. Где находятся компоненты редактирования свойств нод.
2. Как объявляются свойства нод.
3. Как передаются generic-типы.
4. Как реализована текущая система ввода значений.
5. Как получить информацию о доступных объектах и их свойствах.
6. Как устроена сериализация значений.
7. Как будет выполняться проверка типов.
8. Как будет компилироваться или интерпретироваться выражение.

После изучения архитектуры предложить минимальную реализацию, которая не требует переписывать существующую систему нод.

## Результат

Компактный универсальный компонент `MarsValueInput<T>`, который можно использовать в свойствах нод.

Примеры:

```csharp
<MarsValueInput T="string" />
```

```csharp
<MarsValueInput T="int" />
```

```csharp
<MarsValueInput T="DateTime" />
```

```csharp
<MarsValueInput T="string"
                AllowExpression="false" />
```

Компонент должен поддерживать обычные строки, выражения с `@`, типизированные константы, автодополнение и выбор свойств из дерева.
