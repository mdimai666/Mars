# Подумать как сделать редактор встраиваемым.
По задумке он должен был глубоко встраиваться в админку.
Сценарии использования:
- В нодах например есть блоки с динамической логикой и я хотел задавать порядок операций через blockly. В данный момен сортируемый вызов с именами методов и аргументы. Но он очень сковывает некоторые задумки.
- Еще для выборки данных в списке записей в админке или нодах, фильтры типа linq. Сейчас есть способ записи аналогично Linq но строки, и я хочу дополнительно создавать через blockly.
- Пример использования Playwright. Чтобы задавать что он открывал ссылку, потом нажимал кнопки при условии было бы удобно задавать через blockly.

Вот что редактор решать режим запуска и Events не верно, отдельный компонент запуска в браузере.
Надо кнопки запуска убрать и вообще панель верхний. Надо сделать несколько различных редакторов по назначению.
- песочница как сейчас, где запуска параметры запуска.
- Форма редактирования данных, просто редактирует
- еще какие то по задумке.

Сделать визуальные улучшения. Если окно маленькое то автоматически в Боковое меню оставлять только иконки. Так же есть параметр для управления этим.

Создать "контексты" и там уже решается что и как запускается. Это как раз у разных редакторов свой. Я буду для разных использований буду регистрировать раные контексты.
Поэтому текущий редактор с параметрами запуска и списком событий надо переделать в браузерную песочницу. А так же добавить другие радакторы.

Другие редакторы используют текущий редактор но у них по сути есть параметр контекста и все. В этот редактор при загрузке передает json блоки, при сохранении наверное передает json блоки на сервер и сохраняеть. И запуск только по id. Это только у песочницы в браузере будет возможноть передать полный json запуска.

Спланируем!
