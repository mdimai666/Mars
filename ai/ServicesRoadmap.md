# Сервисы Mars — дорожная карта к выходу на рынок

Дата: 2026-08-12. Контекст: обсуждение распространения плагинов
([PluginServer/PluginDistributionPlan.md](./PluginServer/PluginDistributionPlan.md),
[PluginServer/PluginCatalogPlan.md](./PluginServer/PluginCatalogPlan.md)) переросло в вопрос
«какие сервисы понадобятся продукту на рынке». Философия: минимум своей инфраструктуры,
делегирование платформам, догфудинг самого Mars.

## Уже есть (фундамент)

Сайт mars-dotnet.org, документация на GitHub Pages, дистрибуция через NuGet + Docker Hub +
GitHub Releases, CI-скрипты публикации. Базовые потребности релиза закрыты.

## Уровень 1 — нужно к релизу (дёшево или бесплатно)

### Проверка обновлений и security-уведомления
Эндпоинт вида `GET /mars/latest` (версия, changelog, known vulnerabilities) — инстансы Mars
периодически спрашивают «я актуален?». ~Один контроллер, может жить прямо в каталоге плагинов.
Так делают WordPress/Umbraco и др.

### Процесс безопасности
GitHub Private Vulnerability Reporting (включается настройкой репо), `SECURITY.md`, правило
выпуска security-релизов. Для продукта, который исполняет чужой код (ноды, плагины, скрипты),
это вопрос доверия на рынке — и почти бесплатно.

### Площадка сообщества
GitHub Discussions (issues уже есть) + один чат-канал (Discord или Telegram). Бесплатно и без
обслуживания; Discourse понадобится, только когда Discussions перестанут справляться.

## Уровень 2 — сильно усиливает выход на рынок

### Live-демо
Публичный инстанс Mars с предзагруженными примерами: боты, автоматизации, магазин — по
позиционированию из [MarsCloudPlan.md](./MarsCloudPlan.md), а не «просто блог». Один из главных
инструментов конверсии (WordPress/Node-RED). Один Docker-контейнер на VPS, сбрасывается по
расписанию.

### Opt-in телеметрия
Анонимная, включается явно при setup (мастер уже есть): версия, ОС, какие ноды/движки
используются, агрегированные ошибки. Единственная обратная связь о реальном использовании.
Варианты: self-hosted GlitchTip (лёгкий клон Sentry) или приём OpenTelemetry — OTel в Mars
уже встроен, нужен только коллектор-приёмник. Принципиально: opt-in, без контента пользователей,
публично описать, что собирается.

### Галерея рецептов и скиллов
Уже в планах — дифференциация для no-code аудитории: не «установи платформу», а «возьми готовый
сценарий». Живёт в каталоге плагинов как отдельный тип сущности (рецепты — JSON, NuGet не нужен).

### Аналитика сайта/доков
Privacy-friendly (Cloudflare Web Analytics или self-hosted Umami) — что читают и откуда приходят.

## Уровень 3 — по мере роста

### Единая идентичность (Keycloak) — триггер сработал: Mars Cloud
Решение (2026-08-12): Keycloak деплоится вместе с Mars Cloud — контрол-плейн облака сам будет
инстансом Mars, а Mars уже умеет в Keycloak (модуль `Mars.SSO`: `KeycloakProvider`,
`DynamicSsoProviderFactory` с драйверами keycloak/google/github/microsoft/mars). Каталог плагинов
до этого момента живёт на прямых Google/GitHub-логинах и переходит на OIDC Keycloak сменой
конфига. Задел на будущее: SSO в Mars-инстансы клиентов (в т.ч. драйвер `mars` — инстансы
доверяют друг другу).

### Служба подписи плагинов
Если экосистема вырастет, «рекомендовано» подкрепляется криптографической подписью
(часть каталога, не отдельный сервис).

### Локализация
Когда сообщество начнёт просить языки — Weblate/Crowdin; пока хватает двух языков через
GitHub PR.

### Status page
Для своих сервисов (каталог, сайт, демо) — статичная страница или GitHub-based, без SaaS.

## Уровень 4 — если пойдёте в монетизацию

- **Managed-облако** (хостинг Mars «в один клик») — самый естественный продукт: продавать то,
  что уже умеете деплоить. План: [MarsCloudPlan.md](./MarsCloudPlan.md) (контрол-плейн на Mars,
  Keycloak, сетка тарифов, позиционирование).
- **Платные плагины** в каталоге: приём платежей (Stripe) + лицензионный ключ/проверка
  подписки — ещё один небольшой сервис.
- **Платная поддержка/подписки** для бизнеса.
- **Каналы дистрибуции для no-code**: one-click образы на DigitalOcean/Railway, шаблоны для
  популярных хостингов — не сервисы, но сильные каналы привлечения.

## Итог по инфраструктуре

К релизу реально нужны только: эндпоинт проверки версий (встроить в каталог), SECURITY-процесс,
Discussions + чат, демо-инстанс. Всё остальное — по триггерам роста, и почти всё либо
делегируется платформам (GitHub, nuget.org, Docker Hub), либо догфудится на самом Mars.
