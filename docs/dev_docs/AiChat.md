# ИИ-чат (агент)

В админ-панель Mars встроен ИИ-агент в стиле терминала. Он выполняет задачи по управлению сайтом по текстовой команде: меняет настройки, создаёт посты, правит поля прямо на открытой странице редактирования, работает с SQL-базами (найти, заменить, записать), отвечает на вопросы о системе.

## Как открыть

Внизу экрана находится плавающая кнопка **«ИИ агент»**.

- Нажмите её — откроется окно чата.
- Зажмите и перетащите — кнопка переместится и прилипнет к ближайшему краю экрана (позиция запоминается).

Окно чата выполнено как терминал: вводите задачу в строку `❯` и нажимайте **Enter**. В заголовке окна:

- выпадающий список — переключение между чатами;
- **＋** — новый чат;
- **■** — остановить текущее выполнение;
- **✕** — свернуть окно.

## Включение и настройка

Фича управляется feature-флагом `AiChat` в `FeatureManagement` (`appsettings.json`):

```json
"FeatureManagement": {
    "AiChat": true
}
```

Перед использованием нужно настроить подключение к ИИ-сервису: **Настройки → «ИИ-чат (агент)»**.

- Добавьте одно или несколько подключений: **OpenAI**, **Qwen (DashScope)**, **DeepSeek**, **Ollama** или любой OpenAI-совместимый сервис (`Custom`).
- Для каждого подключения задаются название, провайдер, endpoint (если пусто — берётся значение по умолчанию для провайдера), API-ключ и модель.
- Отметьте подключение **«По умолчанию»** — именно его использует агент.
- Опционально задайте «Дополнительные инструкции агенту» — они добавляются к системному промпту.
- Флажок **«Разрешить агенту доступ к SQL-базам»** (включён по умолчанию) выдаёт агенту инструменты SQL; снимите его, если доступ к базам не нужен.

## Что умеет агент

### Настройки сайта
Меняет базовые настройки сайта: имя сайта, описание, email администратора. Пример: *«поменяй имя сайта на „Мой сайт“»*. Перед изменением агент читает текущие значения, после — проверяет результат.

### Любые опции сайта
Управляет любой зарегистрированной опцией по имени класса: `list_site_options` (список), `get_site_option` (чтение), `update_site_option` (запись). Так можно менять SEO, режим обслуживания, медиа, маршрутизацию фронта и т.д.

> Секреты защищены: SMTP-настройки, подключения ИИ-чата, подключения к базам данных (connection strings) и favicon-опции агенту недоступны; `PluginManagerSettingsOption` — только чтение.

### Информация о системе
Отвечает на вопросы о приложении: версия Mars и git-коммит, ОС и архитектура, окружение, запущено ли в **Docker** или под **pm2**, аптайм, использование памяти. Пример: *«какой ты версии? ты запущен в докере?»*.

### Посты
- **Создать пост без страницы**: *«создай пост про …»* — агент сам создаёт пост (черновик), генерирует slug из названия и адаптирует текст под тип контента поста (блочный редактор / WYSIWYG / plain). В ответе приходит ссылка на страницу редактирования.
- **Прочитать пост** (`get_post`) и **список постов** (`list_posts`).

### SQL-базы
Агент умеет работать с SQL-базами через те же подключения, что и ноды/страница `/datasource`:

- **Основная база Mars** (slug `default`) — посты, пользователи, настройки, метаданные; и все настроенные **data sources** (PostgreSQL, MsSQL, MySQL).
- Может посмотреть список баз, изучить структуру (таблицы и колонки), выполнить SELECT (результат приходит таблицей, не более 50 строк за раз) и записывающие запросы — INSERT/UPDATE/DELETE/DDL — с отчётом «затронуто N строк».
- Примеры: *«сколько постов в базе?»*, *«найди в таблице Posts все записи без slug»*, *«замени в таблице X значение Y на Z»*.
- **Безопасность**: перед любым записывающим запросом агент обязан показать точный SQL и спросить подтверждение; после записи — проверить результат чтением. Connection strings агенту не выдаются.
- Доступ выключается флажком «Разрешить агенту доступ к SQL-базам» в настройках ИИ-чата.

### Правка полей на открытой странице редактирования поста
Если открыта страница редактирования поста (`EditPost`), агент может прочитать и изменить её поля: **название, slug, анонс, теги, категории, текст**.

- Пример: *«перефразируй текст»* или *«перефразируй название»* — агент прочитает текущее значение, преобразует его и запишет обратно в форму.
- Контент читается и пишется с учётом активного редактора (Editor.js / monaco / plain-text); для чтения агенту дополнительно отдаётся plain-text извлечение.
- По умолчанию агент **не сохраняет** изменения — вы проверяете и жмёте «Сохранить» сами. Сохранение — только по явной команде (*«…и сохрани»*).

### Автообновление списка постов
Если вы находитесь на странице **списка постов** и просите создать пост, после создания таблица **обновляется автоматически** — новый пост сразу виден (он создаётся черновиком и появляется сверху).

### Уточняющие вопросы
Если для задачи не хватает информации, агент задаёт уточняющий вопрос и ждёт вашего ответа (например, просит уточнить, какое именно значение поставить).

## Как это устроено (кратко)

- Агент построен на **Microsoft Agent Framework** (`HarnessAgent`) и работает как harness: выполняет не один промпт, а многошаговый цикл с вызовом инструментов (function calling), пока задача не решена.
- Ответ стримится в терминал по **SignalR** (хаб `/_ws/aichat`): фрагменты текста, вызовы инструментов и их результаты, вопросы, завершение/остановка/ошибка.
- История чата хранится в **HybridCache** (по одному активному запуску на чат).
- Взаимодействие с открытой страницей редактирования идёт через «мост»: серверный инструмент отправляет запрос странице по SignalR, страница выполняет его и возвращает результат.
- Событие обновления списка постов рассылается через общий админ-хаб (`/_ws/admin`, событие `PostListChanged`).
- Исходники модуля: `src/Mars.Modules/Mars.AiChat.*`, техническое описание — в [`ai/AiChatGuide.md`](../../ai/AiChatGuide.md).

## Ограничения

- Запись **WYSIWYG**-контента пока не поддерживается (чтение — да).
- Агент не сохраняет правки на странице автоматически — только по явной команде.
- Один активный запуск на чат: повторное сообщение во время выполнения вернёт «чат уже обрабатывается».
- Категории передаются по Guid; если нужен список доступных категорий — уточните у агента или посмотрите в форме.
