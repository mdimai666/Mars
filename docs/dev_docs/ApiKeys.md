# API-ключи (X-API-Key)

Помимо входа по логину/паролю и JWT-токенов, Mars поддерживает авторизацию по персональным
API-ключам. Ключ передаётся в HTTP-заголовке `X-API-Key` и работает на всех эндпоинтах API,
защищённых авторизацией: внешние скрипты, интеграции, IoT-устройства и автоматизация могут
обращаться к вашему экземпляру Mars без хранения логина и пароля.

API-ключ равносилен сессии его владельца: запросы с ключом выполняются от имени пользователя
и с его правами (ролями).

## Формат ключа

```text
mars_{keyId}.{secret}
```

- `keyId` — идентификатор записи ключа;
- `secret` — секретная случайная часть.

Полный ключ показывается **только один раз** — в момент создания. В базе данных хранится лишь
хэш секретной части (SHA-256), поэтому восстановить показанный ключ невозможно — только
создать новый. В списке ключей видны название, префикс (`mars_3f2a2b1a…`), дата создания
и срок действия.

## Создание ключа в панели управления

1. Откройте меню пользователя (аватар в правом верхнем углу) → **API-ключи** (страница `/dev/ApiKeys`).
2. Нажмите **Создать ключ**.
3. Укажите название (например, «Скрипт мониторинга») и срок действия — вручную или чипами
   **Неделя / Месяц / 3 месяца / Год** (по умолчанию — 3 месяца; срок можно оставить пустым —
   ключ без ограничения по времени).
4. Скопируйте ключ из появившегося окна — оно показано в последний раз.

Там же ключ можно **отозвать** (кнопка удаления в строке ключа) — после отзыва он сразу
перестаёт работать.

## Создание ключа через CLI

Если экземпляр Mars запущен, ключами можно управлять из командной строки (`Mars.exe`):

```ps1
# создать ключ (полный ключ печатается один раз)
Mars.exe user apikey add admin --name "CI deploy" --expires 2026-12-31

# список ключей пользователя
Mars.exe user apikey list admin

# отозвать ключ (по названию или id)
Mars.exe user apikey delete admin "CI deploy"
```

Флаг `--expires` необязательный. Команды выполняются в живом экземпляре Mars.

## Использование ключа

Добавьте заголовок `X-API-Key` к запросу:

```bash
curl -H "X-API-Key: mars_9f1c...e21.ab12..." https://your-mars-site/api/Post/list/offset
```

JavaScript (`fetch`):

```js
const res = await fetch("/api/Post/list/offset", {
    headers: { "X-API-Key": "mars_9f1c...e21.ab12..." }
});
```

C# (`HttpClient`):

```csharp
using var http = new HttpClient { BaseAddress = new Uri("https://your-mars-site") };
http.DefaultRequestHeaders.Add("X-API-Key", "mars_9f1c...e21.ab12...");
var json = await http.GetStringAsync("/api/Post/list/offset");
```

Swagger UI (`/api/index.html`) также поддерживает этот способ: нажмите **Authorize** и введите
ключ в поле схемы **ApiKey (X-API-Key)**.

В визуальных потоках (нода **Http Request**) для исходящих запросов к другим сервисам
способ авторизации `ApiKey` настраивается в ноде конфигурации авторизации — он не связан
с ключами Mars и предназначен для внешних API.

## Ограничения и настройки

- Количество активных ключей на пользователя ограничено. Лимит задаётся администратором:
  **Настройки → OpenApi → «Максимум API-ключей на пользователя»** (по умолчанию 10).
- Ключ с истёкшим сроком действия отклоняется сервером.
- Ключ привязан к пользователю: при удалении пользователя его ключи удаляются вместе с ним.

## Безопасность

- Храните ключ как пароль: не коммитьте его в репозитории и не вставляйте в публичный код.
- Устанавливайте срок действия — просроченный ключ перестанет работать сам.
- При подозрении на утечку немедленно отзовите ключ (в панели `/dev/ApiKeys` или через CLI)
  и создайте новый.
