# Фронты

Фронт — это сайт (или его визуальная часть), который рендерит Mars. Фронт представляет собой
**папку с файлами**: шаблоны страниц, блоки, layout'ы и публичная статика. Никакой «магии» в БД —
всё, что отрисовывается, лежит в файлах.

## Где живут фронты

По умолчанию фронты хранятся в `data/fronts/<slug>` рядом с приложением:

```
data/fronts/
    default/            <- фронт со slug "default"
        _root.hbs       <- точка входа
        pages/
        blocks/
        layout/
        wwwroot/        <- публичная статика (css/js/img)
    my-second-front/
        ...
```

Вместо встроенной папки можно подключить **внешнюю папку** (абсолютный путь) — удобно для разработки
шаблона в отдельном репозитории без копирования.

Структура файлов фронта и атрибуты `@page`/`@layout`/`@cache` описаны в
[документации Handlebars-фронта](md/AppFront/Handlebars/HandlebarsAppFront.md).

## Настройка фронтов (админка)

Список фронтов — опция `FrontsOption` в базе данных. Управление: админка → Настройки → **Фронты**
(`/dev/Settings/Front`). Для каждого фронта настраиваются:

| Поле | Назначение |
|---|---|
| Slug | имя фронта и имя папки в `data/fronts/` |
| Title | человекочитаемое название |
| Url | маунт фронта: пусто = корень `/`, либо префикс вида `/app2` |
| Path | пусто = `data/fronts/<slug>`; либо абсолютный путь к внешней папке |
| Движок | чем рендерить фронт (встроенный `handlebars` + плагины) |
| вкл | включен ли фронт |

Все изменения применяются **сразу, без перезапуска приложения**: включение/выключение фронта, смена
движка, добавление нового URL.

Кнопка «Создать фронт» копирует в `data/fronts/<slug>` стартовый шаблон (готовый сайт: главная,
страница поста, 404, стили) и добавляет фронт в список. Удаление фронта убирает его из списка;
опционально удаляется и папка (для внешних папок — только из списка).

## Редактор фронта

Кнопка «Редактор» у фронта открывает страницу `/dev/front/editor/<slug>` — редактор в стиле VSCode:

- слева — дерево файлов фронта (создание/переименование/удаление);
- по центру — редактор кода (Ctrl+S сохраняет файл);
- справа — живой предпросмотр сайта в iframe.

Правки файлов применяются на лету: при сохранении файла предпросмотр перезагружается автоматически
(hot-reload через SignalR).

## Движки рендера

Движок рендера выбирается на каждый фронт отдельно и может быть изменён в рантайме. Встроенный
движок — `handlebars` (файловые шаблоны). Плагин может добавить собственный движок, зарегистрировав
`IWebRenderEngineFactory` — см. [ai/PluginCreationGuide.md](../../../ai/PluginCreationGuide.md)
(раздел «Custom Front Render Engine»).

## Запрос к фронту

1. URL запроса сопоставляется с `Url` фронтов (побеждает наиболее специфичный префикс,
   фронт с пустым `Url` — корень `/`).
2. Если запрос — файл, он раздаётся из `wwwroot` фронта.
3. Иначе страница рендерится движком фронта (матчинг `@page`-страниц, `@cache`, layout'ы).
4. Выключенные фронты и неизвестные URL — 404.

## Миграция со старой конфигурации

До появления `FrontsOption` фронты задавались секцией `AppFront` в `appsettings.json`. При старте
приложения выполняется разовая авто-миграция: handlebars-записи из `AppFront` переносятся в
`FrontsOption` (Url/Path сохраняются), поэтому существующие инсталляции продолжают работать.
Секция `AppFront` в `appsettings.json` больше не требуется.
