# Страницы админки и боковое меню

## Админ-фронт (slug `admin`)

- Особый фронт админки: папка `data/admin/front`, редактор — `/dev/tech/frontend/editor/admin`.
  Файлы правятся инструментами фронта (ListFrontFiles / ReadFrontFile / WriteFrontFile / …),
  они доступны ТОЛЬКО когда открыт редактор фронта. Если редактор не открыт — попроси пользователя
  открыть `/dev/tech/frontend/editor/admin` и повторить задачу.
- Структура та же, что у обычного фронта (скилл mars-front-editor): `_root.hbs` — layout,
  `pages/*.hbs` — страницы, `blocks/*.hbs` — блоки, `wwwroot/` — статика.
- Страница админ-фронта открывается в админке по адресу `/dev/p/{url}`, где `{url}` — значение
  директивы `@page "/url"` из первой строки файла (НЕ имя файла). Пример: файл `pages/contacts.hbs`
  с `@page "/contacts"` → адрес `/dev/p/contacts`.
- Важно: боковое меню админки (сайдбар) НЕ в блоках фронта — не ищи его в `blocks/` и `_root.hbs`.
  Сайдбар — это меню CMS со slug `dev` (см. ниже).

## Боковое меню админки — меню CMS `dev`

Инструменты: ListNavMenus (список меню), GetNavMenu(slug) (пункты), AddMenuItem, UpdateMenuItem,
RemoveMenuItem. Сайдбар админки — системное меню со slug `dev`.

- Пункты — плоский список с parentId (дерево) и порядком отображения; читай GetNavMenu перед правкой.
- Системное меню `dev` живёт как дефолт из кода + сохранённая копия: первое изменение сохраняет копию,
  дефолтные пункты (isSystem=true) остаются и после сброса. Системный пункт нельзя удалить —
  только отключить: UpdateMenuItem(disabled="true").
- Ссылка пункта на страницу админ-фронта: `/dev/p/{url из @page}`. Ссылки на штатные страницы
  админки начинаются с `/dev/` (например `/dev/Media`, `/dev/Post/post`).
- После AddMenuItem / UpdateMenuItem / RemoveMenuItem меню сохраняется сразу, но сайдбар у пользователя
  НЕ обновляется сам: ОБЯЗАТЕЛЬНО вызови RefreshInitialSiteData (инструмент ядра) — админка перетянет
  InitialSiteData и сайдбар обновится без перезагрузки страницы.
- Удаление пункта (RemoveMenuItem) — только после подтверждения пользователя через ask_user;
  удаляются и все подпункты.
- Если у пользователя открыта страница редактирования меню (/EditNavMenu/{id}), правь меню через мост
  открытой страницы (GetOpenPageFields / SetOpenPageField / SaveOpenPage) — пользователь видит правки
  в форме и сам сохраняет; серверные инструменты меню в этом случае не используй (перезапишут форму).

## Рецепт «страница + пункт в боковом меню»

1. Пользователь открыл редактор `/dev/tech/frontend/editor/admin` (иначе попроси открыть).
2. Создай страницу: WriteFrontFile `pages/{имя}.hbs`, первая строка `@page "/{url}"`,
   далее содержимое (Handlebars; layout админ-фронта подключается сам).
3. Проверь страницу: ReadFrontFile (файл на месте) и сообщи адрес `/dev/p/{url}`.
4. Добавь пункт сайдбара: AddMenuItem(slug="dev", title="{название}", url="/dev/p/{url}").
   Порядок и вложенность — по задаче пользователя (parentId для подпункта).
5. Вызови RefreshInitialSiteData — сайдбар у пользователя обновится без перезагрузки.
6. Коротко сообщи: какой файл создан, адрес страницы и какой пункт меню добавлен.
